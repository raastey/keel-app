00

What Keel is

A paid, direct-distributed desktop application. Not a chatbot, not a model wrapper. Keel does not ship a proprietary base model — the user brings, downloads, or connects an Engine. Keel supplies the workspace around it.

Thesis

Private AI with inspectable memory. See, edit, and train the context your AI uses — without handing your work to a cloud model.

Engine
The base model, running locally or reached with the user's key. Interchangeable.
Personal Model
A small local adapter trained only from material the user approved. Sits on a compatible Engine.
Working Context
The selected source package for one answer. Inspectable and editable before it is used.
Library
The user's own indexed material. Indexed locally, always.
Learning · Quality Check
The reviewed local training flow and its evaluation.
Candidate Model
A newly trained adapter that is not active until the user promotes it.
Non-negotiables
Local-first by default.
Library indexing and training are local only, always.
Remote providers require the user's own API key and an itemized send gate.
Nothing leaves the machine without a Remote · provider marker — word and shape, never color alone.
Writer and Developer stay separate: Library, index, adapter, evaluations, promotion history.
Training completion produces Needs review, never Ready. No model is promoted automatically.
Code edits pass six gates; tests are authorized separately.
No orbs, sparkles, fake terminals, gamification, or “magic memory” language.

04

Welcome & setup

Seven steps, no terminal, no Python, no blanket disk permission, no cloud account. The user reaches a real project workspace with working context before they are asked for anything else.

04b

Choose your Engine

The first-run step that makes the product honest about what it is. Keel ships no base model; this screen is where one arrives. It also teaches the three words the rest of the product depends on.

05

Global shell & Home / Continue

Home answers exactly one question: what was I doing, and what should I continue? At most three Continue cards, then a quiet recent list. No token dashboards, no usage charts, no streaks.

05b

Project Memory & Continue

Open a project and Keel restores where the work stood. Project Memory is a readable, editable record — decisions, open threads, rejected directions — not an opaque store. Every line can be corrected or deleted by the user.

06

Writer workspace

A writing environment, not a chat page. The document is the subject of the window and it is the user's; the assistant lives in a composer strip and a right-hand context rail. Model output never lands in the prose without an explicit review action.

06b

Pre-answer bar & AI with receipts

Two patterns carry the differentiator into every answer. Before: the pre-answer bar states what will be used and offers to change it. After: a receipt states what was used. Both are persistent, both are in Writer and Developer, neither is a modal the user can lose.

07

Context Inspector

The signature trust feature. Opens over the workspace from anywhere with ⌘I. Seven sections in fixed order, including — critically — what was left out and why. Every included item can be previewed, opened, pinned, removed for this response, or marked canonical.

08

Developer workspace

Five mandatory gates before a repository changes: scope → file list the user can trim → diff → apply choice → separately authorized test run. The base Engine stays fully useful for Ask, Explain, and Plan even when the Code Personal Model is not cleared for edits.

08b

Six gates, stated plainly

The gate rail is permanently visible in the Developer workspace, so the user always knows how far a proposal has travelled and what has not happened yet. Tests are a separate authorization from applying a diff — running a command is not implied by accepting an edit.

09

Library

A source browser, not a file manager. Every item carries one status the user controls: Included, Gold, Reference only, Needs review, Excluded. Statuses are stated in words in the row — the colored dot is redundant by design.

10

Training Center

Supervised and visually serious. A finished run produces a candidate in amber — never a green success. The active model changes only through an explicit promotion, and rollback is always preserved.

10b

Learning Inbox

Keel does not learn silently. New work waits here until you approve it. The Inbox is a review queue with a small vocabulary of states, and it is the only door into training.

11

Models, Privacy, Storage

Plain language on the surface — Engine, Personal Model, Working Context — with technical metadata one disclosure away. The Privacy screen is a factual inventory of what happens where, not a reassurance.

11b

Bring your own engine

Three ways to supply intelligence: the engines Keel ships, a runtime or model file already on the machine, or a remote provider reached with the user's own API key. The product's argument does not change — the user must always be able to see where work is about to go, and stop it.

Local — this computer
Built-in engines, a detected runtime (Ollama, LM Studio, llama.cpp server), or a model file the user imports. Default. Nothing leaves.
Local network
An OpenAI-compatible endpoint on a machine the user owns — a workstation, a home server. Treated as remote for every warning.
Remote provider
The user's own key and their own billing relationship. Keel never proxies, never resells, never sees the key after it goes into the keychain.
11c

Models — three groups

The v2 Models screen is organised by the three concepts, in this order, with these headings, so the vocabulary is learned by reading the screen. Technical metadata stays one disclosure deeper.

12

Command Palette & critical states

⌘K reaches every project, source, session, mode, and setting. Below it, the states the product must be designed for — each one says what happened, what it means, and the one thing to do next.

No Engine installed

Keel needs an Engine to answer. Your Library, projects, and context are already set up and will not change.

Not enough memory

Standard 14B needs about 12 GB free; 5.1 GB is available right now. Compact 7B will run well on this machine.

Download interrupted

3.2 GB of 8.4 GB is already on disk and verified. Resuming continues from there.

Training interrupted

The machine slept at step 1,840 of 4,200. The checkpoint is intact — resuming does not start over. Your Active model was never touched.

Candidate failed a check

v5 answered without using a provided source in 3 of 20 checks. It cannot be promoted until you review those cases.

Source moved

2 sources are no longer where Keel last saw them. The indexed text is still available; citations will point to a path that no longer exists.

Permission lost

macOS revoked access to ~/Documents/Reporting. Keel will not read it again until you re-grant access to that folder alone.

Likely secret quarantined

.env.production matched a credential pattern. Its contents were not read, indexed, or shown — only the file name.

Rules
The product never says “I”. It is not a character. Messages describe what happened and what the user can do: “Three memos were not included — they exceed the context budget.”
Every error names the cause, the consequence, and one next action. No “Something went wrong.”
No fake time estimates. Show real counts and real steps; if the duration is unknowable, say so.
Completion is not quality. A finished training run is amber “Needs review”, never green.
Attribution is mandatory. When an answer comes from general knowledge rather than the user's sources, the response says so in its first line.
Plain language on the surface, precision one click deeper. Quantization, parameter counts, and hashes live under “Advanced details”.

15

Accessibility & platform parity

Accessibility floor
Body text meets 4.5:1; all UI text ≥ 12px, default 13px.
Status is never color alone — shape and word always present.
Full keyboard operation, visible 2px focus ring, logical tab order per pane.
Native accessibility trees on all three platforms; every custom control exposes role, value, and state.
Respects system text size up to 200% — panes reflow, they do not clip.
prefers-reduced-motion removes all transitions; nothing depends on animation to be understood.
Screen-reader announcements for long operations at start, at completion, and on failure only — never per progress tick.
Same product, native manners
macOS — unified toolbar, native sidebar material, sheets for confirmation, ⌘ accelerators, full-height traffic-light inset.
Windows — Mica backdrop, 4px window radius, title bar with app menu, Ctrl accelerators, dialogs not sheets.
Linux — GNOME header bar with the primary action on the right, Adwaita-consistent spacing, dark by default where the desktop asks for it.
Identical: layout skeleton, information architecture, vocabulary, all seven Inspector sections, all training gates. Divergent: chrome, dialog style, iconography, accelerator keys, file-picker behavior.
Performance contract
Cold launch to interactive Home: under 2s — Home renders from cache before the Engine loads.
Any user action acknowledges within 100ms, even if the work takes minutes.
First token visible within 1.5s of Send on the recommended Engine; the context package is assembled and shown before generation starts.
Indexing, downloads, and training are always cancellable, always resumable, and never block the workspace.
Training yields memory to foreground work automatically and states that it has done so.
16

Build order

Phase 1 — Trust
Library, Engine setup (all four routes and every state), Working Context, Context Inspector, Writer base flow, Privacy and Storage. This is the product's argument; nothing ships before the Inspector is complete.
Phase 2 — Continuity
Project Memory, Continue cards with readiness, the pre-answer bar, receipts in every surface, Writer workspace polish, Versions, Command Palette, dark parity.
Phase 3 — Developer
Ask, Explain, Plan; repository inspector; read-only context; the six gates with separately authorized tests; Developer receipts and the not-ready-for-edits state.
Phase 4 — Learning
Learning Inbox, local training orchestration, candidate review, Quality Checks, blind comparison, promotion and rollback. Last, because it is the easiest to get dangerously wrong.
Open questions for the team
One binary with two spaces, or two products? · Is Gold per-project or global to a space? · Should blind comparison be mandatory before any promotion? · May a remote provider ever see Gold sources, or only Included ones? · Does an Engine swap invalidate Personal Models silently, or keep them visible as incompatible?
Design principle
If users remember one thing after seeing Keel: “I can see and control what the AI knows before it answers or acts.”
